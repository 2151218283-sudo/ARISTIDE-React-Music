# ECHOFORM 产品需求文档

> 项目名称：ECHOFORM / 声形（开发阶段正式品牌）
> 项目类型：基于 React 的沉浸式在线音乐播放器
> 文档状态：Product Baseline v1.0
> 更新日期：2026-07-29
> 数据来源：NeteaseCloudMusicApi（非官方、已停止维护，必须通过适配层接入）

## 1. 文档目的

本文档把现有 Aristide Benoist 网站复刻成果改造成在线音乐播放器的产品方案，作为后续视觉设计、技术设计、组件规格、功能开发、测试验收和毕业答辩的统一依据。

本文档是本地单实例毕业设计版本的可执行产品基线。P0/P1 范围、核心路由、Real/Demo
边界和关键交互以本文为准；P2 仍是候选增强范围。任何涉及数据库 Schema、`.env`、密钥、
CI/CD、公开部署或发布的实现动作，仍需单独确认。

## 2. 产品定义

### 2.1 一句话定义

ECHOFORM 是一个以“每日私人音乐展览”为核心体验的沉浸式在线音乐播放器：用户通过网易云音乐二维码登录，在有限横向画廊中浏览每日推荐，并在连续空间动画中进入播放、歌词、评论和个人音乐空间。

### 2.2 核心命题

普通音乐播放器以列表和功能入口为中心；ECHOFORM 以“音乐如何被看见、被进入、被感受”为中心。

产品的核心交互表达为：

> 浏览时，用户推动音乐；播放时，音乐推动画面。

### 2.3 产品目标

1. 保留现有复刻站最有价值的有限画廊、滚轮波浪、共享空间展开、自然退出和项目配色过渡。
2. 完成毕设要求中的搜索、播放控制、歌词、歌单、收藏、评论、历史、推荐和设置功能。
3. 通过二维码登录读取用户的网易云资料、每日推荐、歌单、收藏和评论数据。
4. 建立可持续的播放内核，使路由切换和页面动画不打断音乐。
5. 形成具有独立品牌和可答辩技术亮点的作品，而不是网易云界面换皮。

### 2.4 非目标

1. 不复刻网易云音乐、Spotify 或 Apple Music 的界面。
2. 不构建完整即时通讯或站内好友系统。
3. 不绕过会员、版权、地区或付费音质限制。
4. 不在所有页面使用 WebGL；搜索、歌单管理、评论和设置以可用性优先。
5. 第一版不训练机器学习推荐模型，“智能推荐”采用网易云日推与可解释的规则推荐。

## 3. 目标用户与场景

### 3.1 核心用户

- 已有网易云音乐账号，希望使用不同于传统客户端的方式体验个人推荐。
- 重视封面、歌词、氛围和交互动效的年轻音乐用户。
- 使用桌面浏览器进行沉浸式聆听，也会在移动端完成搜索、播放和收藏。

### 3.2 关键使用场景

1. 用户每天第一次打开网站，扫码后查看当天的私人推荐。
2. 用户滚动画廊寻找感兴趣的封面，点击进入歌曲预览并开始播放。
3. 用户在完整播放页跟随同步歌词，查看热门评论或播放队列。
4. 用户按歌曲名、歌手或专辑搜索内容，并在不离开搜索页的情况下播放歌曲。
5. 用户查看个人主页中的网易云歌单、喜欢音乐、最近播放和音乐品味画像。
6. 用户创建或维护歌单、收藏歌曲、分享歌单链接。
7. 用户设置主题、默认音质和定时停止。

## 4. 产品原则

### 4.1 音乐内容优先

封面、歌名、歌手和歌词是主要内容。装饰、粒子和背景动画不得降低内容可读性。

### 4.2 沉浸不等于隐藏功能

高频播放控制必须随时可达。评论、队列和高级设置可以逐步展开，但不能依赖隐藏手势完成关键任务。

### 4.3 一页一个主要运动

- 首页：横向画廊与波浪。
- 歌曲预览：封面共享空间展开。
- 完整播放页：歌词纵向流动与轻量音乐呼吸。
- 用户主页：音乐品味轨迹。
- 搜索和音乐库：不使用持续装饰动画。

### 4.4 动画必须表达因果

所有主要动画都应能说明“内容从哪里来、到哪里去”。动画必须可中断，用户操作不得被等待动画阻塞。

### 4.5 外部能力可替换

前端不得直接依赖 NeteaseCloudMusicApi 的原始字段。所有外部数据先进入 `MusicProvider` 适配层，转换为应用内部模型。

## 5. 成功标准

### 5.1 功能成功标准

- 用户可完成二维码登录，并看到网易云头像和每日推荐。
- 用户可搜索歌曲、歌手和专辑，并正确进入对应页面。
- 音乐在页面切换后继续播放，播放状态、队列和进度保持一致。
- 普通 LRC 歌词能实时高亮；存在逐字歌词时可逐字显示。
- 用户可查看、发表、回复和点赞歌曲评论。
- 用户可查看并管理喜欢、歌单和本地播放历史。
- 用户可切换播放模式、主题、音质偏好和定时停止。

### 5.2 体验成功标准

- 首页首次可交互时间目标：桌面良好网络下不超过 3 秒。
- 普通交互视觉反馈：100ms 内出现。
- 高频控制动画：150-250ms。
- 页面级过渡：350-600ms。
- 首页首次入场与歌曲展开：900-1600ms，仅用于低频沉浸场景。
- WebGL 动画目标：桌面 60fps，低性能设备不低于 30fps。
- 页面布局在 390px、768px、1440px 三个基准宽度无重叠、遮挡和非预期横向滚动。

## 7. 信息架构

### 7.1 路由

| 路由 | 页面 | 是否登录 | 说明 |
| --- | --- | --- | --- |
| `/` | 每日推荐画廊 | 否 | 游客显示公共精选，登录后显示个人日推 |
| `/search` | 搜索 | 否 | 查询写入 `q` 和 `type` 参数 |
| `/track/[id]` | 歌曲完整播放页 | 否 | 播放、歌词、评论、队列 |
| `/album/[id]` | 专辑详情 | 否 | 专辑信息和曲目 |
| `/artist/[id]` | 歌手详情 | 否 | 歌手信息、热门歌曲、专辑 |
| `/library` | 音乐库 | 是 | 喜欢、歌单、历史 |
| `/playlist/[id]` | 歌单详情 | 视权限 | 公共歌单可匿名查看，修改需要登录和权限 |
| `/profile/[id]` | 用户主页 | 否 | 自己或公开用户资料 |
| `/settings` | 设置 | 否 | 账号相关设置需要登录 |

### 7.2 一级导航

桌面端：

```text
ECHOFORM              DAILY SIGNAL              SEARCH  AVATAR
```

- 左上角品牌点击返回 `/`。
- 中上方显示当前上下文，例如 `DAILY SIGNAL`、`SEARCH`、`NOW PLAYING`。
- 右上角搜索位于头像左侧。
- 未登录头像位置显示 ECHOFORM 账户图形；点击展开二维码登录。

移动端：

- 顶部保留品牌、搜索与头像。
- 不设置常驻底部一级导航：首页本身就是发现；音乐库从个人主页或账户菜单进入。
- 当前播放迷你栏位于底部安全区上方，不遮挡内容和系统手势区。

## 8. 全局功能

### 8.1 全局播放器

使用唯一的 `HTMLAudioElement`，挂载于应用级 Provider，不随页面卸载。

全局状态包括：

- `currentTrack`
- `queue`
- `queueIndex`
- `status`: `idle | loading | playing | paused | error`
- `currentTime`
- `duration`
- `buffered`
- `volume`
- `muted`
- `playMode`: `sequence | shuffle | repeat-one`
- `quality`
- `sleepTimer`
- `playbackError`

行为要求：

1. 页面切换不暂停或重置当前歌曲。
2. 点击新歌曲播放时，按来源上下文构建队列，例如日推、搜索结果或专辑曲目。
3. 顺序模式到达队尾后停止；日推画廊不无限循环。
4. 随机模式不连续重复当前歌曲，并保留随机访问历史供“上一曲”使用。
5. 单曲循环在歌曲结束后从 0 秒重新播放。
6. 拖动进度时显示预览时间，释放后更新音频位置。
7. 音量、模式和音质偏好持久化到本地。
8. 音源失效时显示原因，并提供重试或播放下一首，不得静默失败。

### 8.2 持久播放基线

桌面端不使用厚重卡片式底栏，采用无边框播放基线：

```text
歌曲信息       随机 上一曲 播放 下一曲 循环       歌词 队列 音量
──────────────────────── 播放进度 ────────────────────────
```

- 未产生播放行为时隐藏。
- 首次播放后从底部进入。
- 播放、暂停按钮始终可见。
- 页面进入沉浸模式且无操作时，次要控制降低视觉权重，不完全消失。
- 所有图标按钮提供可读名称、焦点状态和至少 44x44px 点击区域。

### 8.3 主题系统

| 模式 | 背景 | 主文字 | 用途 |
| --- | --- | --- | --- |
| `INK` | `#0C0C0D` | `#F2F1ED` | 游客、API 故障、Demo Mode 和手动深色模式 |
| `PAPER` | `#F1F0EB` | `#171717` | 用户手动选择的浅色阅读模式 |
| `ARTWORK` | 由封面色生成 | 自动选择 | 登录后的首页、歌曲预览和完整播放页默认主题 |

主题生成规则：

1. 从封面提取主色和次色。
2. 限制饱和度和亮度，避免刺眼颜色覆盖整屏。
3. 根据背景计算可读前景色，普通文字对比度至少 4.5:1。
4. 主题变化使用平面颜色插值，不使用固定紫蓝渐变。
5. 提取失败时回退到 `INK`。
6. 登录用户进入首页、歌曲预览或完整播放页时默认使用 `ARTWORK`。
7. 游客状态、API 故障和显式 Demo Mode 使用 `INK`，不从演示封面自动生成主题。
8. `PAPER` 只由用户手动选择，页面路由不得擅自把当前主题切换为 `PAPER`。

## 9. 页面详细需求

### 9.1 首页：每日推荐画廊

#### 页面目标

以最少文字呈现用户当天的私人推荐，让用户通过滚动和封面选择音乐。

#### 数据来源

- 登录用户：`/recommend/songs`。
- 游客：Real Provider 的公共新歌或热门推荐；Real 不可用时只在用户显式进入 Demo Mode
  后读取本地演示数据。
- 日推结果按“用户 ID + 日期”缓存，同一天不因重复进入页面频繁请求。

#### 布局

- 左上：ECHOFORM。
- 中上：`DAILY SIGNAL / 日期` 与有限进度刻度。
- 右上：搜索与账户入口。
- 中央：WebGL 有限横向歌曲封面画廊。
- 左下：当前歌曲序号、歌名、歌手。
- 底部：播放后显示持久播放基线。

#### 状态

| 状态 | 表现 |
| --- | --- |
| 初始加载 | 品牌进入，画廊预留稳定尺寸，封面逐步出现 |
| 游客 | 公共精选，账户入口提示可扫码登录 |
| 已登录 | 展示当天个人日推 |
| 加载失败 | 保留页面结构，显示重试和“使用演示数据”；只有用户点击后才进入 Demo Mode |
| 空数据 | 显示公共精选，不出现空白画廊 |
| 边界 | 第一首和最后一首居中，向外滚动不积累位移 |

#### 交互

1. 纵向滚轮驱动有限横向移动。
2. 真实轨道速度驱动封面纵向位移、缩放和轻微旋转。
3. 停止滚动后封面恢复水平静止。
4. 悬停封面恢复色彩和亮度；离开后回到克制状态。
5. 点击封面进入歌曲预览舞台，不立即跳转外部链接。
6. 正在播放时，画廊波浪从纯滚轮响应逐渐混合音乐响应。
7. 移动端使用横向拖动或纵向滑动映射，并提供明确的上一首/下一首替代控制。

#### 验收标准

- `HOME-AC-01`：轨道首尾有限且不循环。
- `HOME-AC-02`：边界外滚动不产生波浪和延迟回弹。
- `HOME-AC-03`：点击任意可见封面可正确展开对应歌曲。
- `HOME-AC-04`：返回首页后恢复原歌曲位置和滚动画面。
- `HOME-AC-05`：API 失败时不自动伪装成功；用户可显式进入带 `DEMO` 标识的模式并完成播放流程。

### 9.2 二维码登录

#### 入口与动画

- 未登录时，右上角显示应用自己的账户图形，不直接使用网易云品牌作为本站 Logo。
- 点击后，图形从原位置展开为二维码登录层，背景画廊变暗并停止交互。
- 登录成功后，二维码层收缩回右上角并转换为用户头像。
- 点击头像时，头像作为约 600ms 的圆形共享元素扩展到 `/profile/[id]` 头部；不使用覆盖
  全屏的圆形遮罩。

#### 接口流程

1. 请求 `/login/qr/key?timestamp=...` 获取 key。
2. 请求 `/login/qr/create?key=...&qrimg=true&timestamp=...` 获取二维码。
3. 每 2 秒请求 `/login/qr/check?key=...&timestamp=...`。
4. 状态码 `801`：等待扫码。
5. 状态码 `802`：已扫码，等待手机确认。
6. 状态码 `803`：成功，服务端保存网易云 cookie，并调用登录状态和用户资料接口。
7. 状态码 `800`：二维码过期，停止轮询并显示刷新操作。

#### 安全要求

- 网易云 cookie 不写入 `localStorage`、前端日志或仓库。
- 浏览器只接收本站 `HttpOnly` 会话标识。
- 二维码层关闭、过期或成功后必须停止轮询。
- 登录接口不得高频重复调用。
- 退出登录后清理服务端会话和前端用户缓存，但不清除非账号相关主题偏好。

#### 验收标准

- `AUTH-AC-01`：801、802、803、800 四种状态均有明确界面反馈。
- `AUTH-AC-02`：成功后 1 秒内头像替换账户图形。
- `AUTH-AC-03`：刷新页面后能恢复有效登录状态。
- `AUTH-AC-04`：二维码层可通过关闭按钮和 Escape 退出。
- `AUTH-AC-05`：轮询不会在弹层关闭后继续运行。

### 9.3 搜索

#### 入口

- 桌面端位于右上角头像左侧。
- 移动端位于右上角账户入口左侧。
- 支持键盘 `/` 聚焦搜索，但不以快捷键作为唯一入口。

#### 页面转场

1. 搜索图标向中心延展为搜索输入线。
2. 画廊向后退场并降低透明度。
3. 路由进入 `/search`，输入框自动获得焦点。
4. Escape 或返回操作恢复来源页面的滚动位置、搜索词和筛选状态。

#### 查询能力

- 按歌曲名称搜索。
- 按歌手名称搜索。
- 按专辑名称搜索。
- 输入 300ms 后触发查询。
- 新请求发出时取消或忽略旧请求，避免旧结果覆盖新结果。
- 查询参数写入 URL：`/search?q=关键词&type=all`。

#### 结果标签

| 标签 | 内容 |
| --- | --- |
| 综合 | 最佳匹配、最多 5 首歌曲、4 位歌手、4 张专辑 |
| 歌曲 | 封面、歌名、歌手、专辑、时长、播放与更多操作 |
| 歌手 | 圆形头像、歌手名、别名和进入详情 |
| 专辑 | 方形封面、专辑名、歌手和年份 |

#### 结果交互

- 点击歌曲行进入歌曲完整页或预览舞台。
- 点击独立播放按钮立即播放，停留在搜索页。
- 点击歌手进入 `/artist/[id]`。
- 点击专辑进入 `/album/[id]`。
- 当前播放歌曲在列表中显示播放状态，不只依赖颜色。
- 空查询显示最近搜索和热搜；无结果显示可恢复的空状态。
- 搜索结果保留所有可发现歌曲，不能因一次音源请求失败而从结果中删除。曲目可显示“已验证可播”“正在检查”或“当前不可播放”的状态，并提供“仅看可播放”筛选。
- 搜索默认不得为整页结果批量请求音源；点击播放时检查，并复用短期检查结果。未验证曲目不得以可播放样式误导用户。

#### 验收标准

- `SEARCH-AC-01`：歌曲、歌手、专辑三类结果均可返回并导航。
- `SEARCH-AC-02`：快速连续输入不会显示过期结果。
- `SEARCH-AC-03`：搜索结果播放后全局播放器正确出现。
- `SEARCH-AC-04`：返回搜索页保留关键词、标签和滚动位置。
- `SEARCH-AC-05`：搜索接口失败时显示原因和重试，不清空现有有效结果。

### 9.4 歌曲预览舞台

#### 目标

承接原站项目展开交互，用最低信息密度让用户判断是否进入完整播放体验。

#### 内容

- 歌曲序号与日推总数。
- 大幅封面。
- 歌名、歌手、专辑、时长。
- 播放/暂停、喜欢、进入完整播放页。
- 当前歌词与前后各一行。
- 一条热门评论入口。

#### 动画

1. 被点击封面从画廊原位置移动并展开为主画面。
2. 相邻封面退到两侧，远处封面降低视觉权重。
3. 歌名立即开始裁切揭示。
4. 元数据约 400ms 后出现。
5. 播放与进入完整页操作约 600ms 后出现。
6. 完整进入目标约 1100ms、上限 1600ms，可被 Escape、返回按钮或滚轮打断；第一帧即
   接受播放和退出输入。

#### 退出

- 预览舞台允许任意非零滚轮事件触发退出。
- 首个退出滚轮事件只改变模式，不移动恢复后的画廊。
- Escape、计数器和明确返回按钮执行同一退出序列。
- 评论抽屉打开时暂停滚轮退出，避免评论滚动误触。

#### 验收标准

- `PREVIEW-AC-01`：展开和收缩保持同一封面的空间连续性。
- `PREVIEW-AC-02`：进入动画期间仍可退出或点击播放。
- `PREVIEW-AC-03`：滚轮退出不会把画廊突然推进多首歌曲。
- `PREVIEW-AC-04`：首尾歌曲的相邻封面不发生循环拼接。

### 9.5 完整播放页

#### 桌面布局

- 左侧或左中：约 38%-42% 视觉宽度的封面。
- 右侧：同步歌词。
- 顶部：品牌、`NOW PLAYING`、评论入口和头像。
- 底部：完整播放控制与进度。
- 评论与队列共用右侧抽屉，通过标签切换。

#### 歌词

数据回退顺序：

```text
逐字歌词 -> 普通 LRC -> 纯文本歌词 -> 暂无歌词
```

行为要求：

1. 普通歌词解析为按时间升序的 `LyricLine[]`。
2. 使用二分查找定位当前行，避免每次 `timeupdate` 全量遍历。
3. 当前行保持在视觉中心附近，前后行降低透明度。
4. 点击歌词行跳转到对应时间。
5. 用户主动滚动歌词后暂停自动跟随 5 秒，然后恢复。
6. 逐字歌词不可用时不得显示错误，自动回退普通歌词。
7. 翻译歌词存在时作为次级行显示，可在设置中关闭。

#### 评论与队列抽屉

- 标签为“评论”和“队列”。
- 评论支持推荐、最热、最新排序。
- 评论项显示头像、昵称、时间、正文、点赞数、回复入口。
- 登录后可发表评论、回复和点赞；匿名用户点击写操作时打开登录层。
- 队列支持查看来源、点击切歌和移除队列项，不允许移除当前唯一歌曲导致异常。

#### 验收标准

- `PLAYER-AC-01`：路由进入和离开不打断当前音乐。
- `PLAYER-AC-02`：歌词高亮与音频误差目标不超过 200ms。
- `PLAYER-AC-03`：拖动进度后歌词立即同步到新位置。
- `PLAYER-AC-04`：评论抽屉滚动不触发页面退出。
- `PLAYER-AC-05`：移动端封面、歌词和控制不发生重叠。

### 9.6 专辑详情

#### 内容

- 专辑封面、专辑名、歌手、发布时间、简介。
- 播放全部、收藏专辑。
- 曲目列表：序号、歌名、歌手、时长、可用状态。
- 专辑评论入口。

#### 交互

- 点击“播放全部”用专辑曲目替换当前队列并从第一首可播放歌曲开始。
- 点击曲目行进入歌曲页；点击播放图标直接播放。
- 不可播放歌曲保持可查看，但播放控件禁用并显示原因。

### 9.7 歌手详情

#### 内容

- 歌手头像、名称、别名、简介。
- 热门歌曲。
- 专辑列表。
- 相似歌手。

#### 交互

- 播放热门歌曲建立歌手上下文队列。
- 点击专辑和歌曲进入对应本地路由。
- 页面使用常规纵向滚动，不拦截滚轮。

### 9.8 音乐库

#### 标签

- 喜欢的歌曲。
- 收藏的专辑。
- 我的歌单。
- 收藏的歌单。
- 播放历史。

#### 行为

- 未登录进入时显示登录状态，不跳转到外部页面。
- 长列表超过 50 项时采用虚拟化或分段加载。
- 列表排序提供最近添加、最近播放和名称排序。
- 播放历史默认按最近播放时间倒序。

### 9.9 歌单管理与分享

#### 功能

- 创建歌单：名称必填，描述可选，公开状态可选。
- 编辑歌单：名称、描述、标签、封面。
- 删除歌单：必须二次确认，并明确说明影响。
- 添加歌曲：从歌曲更多菜单选择目标歌单。
- 移除歌曲：仅歌单所有者可操作。
- 分享：生成本站 `/playlist/[id]` URL，优先调用 Web Share API，回退复制链接。

#### 范围说明

第一版“分享给好友”定义为外部分享链接，不建设站内好友关系和即时消息系统。若后续要求站内好友分享，需要另立需求和数据权限模型。

### 9.10 用户主页

#### 定位

用户主页是“听歌人格画像”，不是传统社交资料面板。

#### 内容顺序

1. 头像、昵称、签名和基础资料。
2. 本月音乐品味标签。
3. 音乐品味轨迹。
4. 喜欢的歌曲入口。
5. 创建与收藏的歌单。
6. 最近播放。
7. 常听歌手或听歌排行。

#### 视觉与动画

- 右上角头像作为共享元素扩展到页面头部，转场约 600ms，不用全屏圆形遮罩覆盖内容。
- 大面积保持无卡片布局，歌单使用规整封面单元。
- 音乐品味轨迹使用 3-5 条可区分波形线，不使用饼图堆砌。
- 数据不足时显示真实空状态，不伪造品味统计。

#### 品味画像规则

P1 版本使用可解释规则：

- 最近播放曲目与喜欢歌曲作为样本。
- 按歌手、专辑标签或可获得的风格字段聚合。
- 展示占比最高的 3-5 个类别。
- 数据来源和时间范围在页面中可查看。

### 9.11 设置

#### 分组

| 分组 | 设置项 |
| --- | --- |
| 外观 | INK、PAPER、ARTWORK；减少动态 |
| 播放 | 默认音质、默认播放模式、音量记忆 |
| 歌词 | 翻译显示、逐字歌词优先 |
| 定时停止 | 15、30、45、60 分钟或当前歌曲结束 |
| 账号 | 网易云账号信息、重新登录、退出登录 |

#### 定时停止

- 启动后显示剩余时间。
- 到期前最后 3 秒线性降低应用 Audio 的临时输出增益，到期暂停后立即恢复用户保存的
  音量值；不修改系统音量。
- 用户手动关闭或退出登录时取消定时器。
- 定时器只在当前标签页内有效，刷新页面后清除，不跨刷新恢复。

## 10. 推荐与发现

### 10.1 每日推荐

直接使用网易云个人日推作为首页核心内容，不把它描述为本站自研算法。

- 已登录用户：首页展示其网易云个人日推；每首歌曲仍以当前账号返回的实际音源为最终可播依据。
- 未登录用户：首页上下文必须标为“公开精选”，不能称为“你的每日推荐”。T017A 已验证固定包的匿名注册能力；因其未提升固定公开样本的可播数量，产品使用裸匿名读取并在服务端预检候选。画廊只展示已验证可播的公开候选曲目；无法取得任何已验证曲目时显示真实空状态和恢复操作，不用不可播歌曲填充。
- “已验证可播”只表示当前匿名或登录身份、当前地区和当前短期 URL 下可播放，不承诺 VIP、地区、版权或未来时刻仍可播放。播放前或 URL 临近失效时必须重新验证。

### 10.2 规则推荐

用于满足“基于收藏和历史推荐相似音乐”的需求：

1. 从最近喜欢和有效播放历史中选择最多 10 个种子。
2. 获取每个种子的相似歌曲，结果按天缓存。
3. 排除不可播放、已明确不感兴趣和最近短期重复播放的歌曲。
4. 相同歌曲被多个种子命中时提高分数。
5. 对同一歌手设置数量上限，避免结果被单一歌手占满。
6. 向用户标明“根据你的喜欢与最近播放生成”，不宣称 AI 推荐。

### 10.3 热门与新歌

- 搜索空状态展示热搜。
- 发现页面的次级入口展示热门歌单和新歌榜。
- 热门和新歌不进入首页 WebGL 主画廊，避免削弱每日推荐的唯一性。

## 11. 数据与接口设计

### 11.1 接入原则

- NeteaseCloudMusicApi 只部署为服务端依赖，不由浏览器直接调用。
- Next.js Server API 作为 BFF，负责会话、缓存、字段归一化、错误映射和限流。
- 固定可工作的 API 版本或提交，不跟随不受控的最新代码。
- 为答辩准备本地演示数据和授权音频。

### 11.2 内部数据模型

```ts
type Track = {
  id: string;
  name: string;
  artists: ArtistSummary[];
  album: AlbumSummary;
  durationMs: number;
  artworkUrl: string | null;
  aliases: string[];
  explicit: boolean;
  availability: "playable" | "vip" | "copyright" | "region" | "unknown";
  privilege: {
    fee: number | null;
    maxQuality: AudioQuality | null;
  };
};

type ArtistSummary = {
  id: string;
  name: string;
  avatarUrl: string | null;
};

type AlbumSummary = {
  id: string;
  name: string;
  artworkUrl: string | null;
};

type LyricLine = {
  startMs: number;
  endMs?: number;
  text: string;
  translation?: string;
  words?: { startMs: number; durationMs: number; text: string }[];
};
```

其他必需模型：`Artist`、`Album`、`UserProfile`、`Playlist`、`Comment`、`SearchResult`、
`PlaybackSource`、`PlaybackHistoryItem`、`ThemePalette`、`ApiError`。字段与错误码的精确定义见
`MUSIC_DOMAIN_MODEL.md`；本节只保留产品层摘要。

### 11.4 缓存策略

| 数据 | 缓存建议 |
| --- | --- |
| 登录扫码状态 | 不缓存，始终带时间戳 |
| 登录状态 | 短缓存或会话内缓存 |
| 匿名访客凭据 | 仅 server-only 进程内临时保存；上游拒绝或服务重启即失效 |
| 每日推荐 | 按用户和日期缓存 |
| 搜索建议 | 1-5 分钟 |
| 歌曲详情、专辑、歌手 | 10-60 分钟 |
| 歌词 | 长缓存，按歌曲 ID |
| 评论 | 30-60 秒，发表后主动失效 |
| 音乐 URL | 按返回有效期，不长期持久化 |

### 11.5 错误模型

前端只处理归一化错误：

- `AUTH_REQUIRED`
- `SESSION_EXPIRED`
- `QR_EXPIRED`
- `VALIDATION_ERROR`
- `RATE_LIMITED`
- `TRACK_UNAVAILABLE`
- `VIP_REQUIRED`
- `REGION_RESTRICTED`
- `SOURCE_EXPIRED`
- `UPSTREAM_TIMEOUT`
- `UPSTREAM_UNAVAILABLE`
- `NETWORK_ERROR`
- `UNKNOWN_ERROR`

错误文案必须说明原因和恢复动作，例如“歌曲因版权限制暂不可播放，可播放下一首”，而不是只显示“播放失败”。

## 12. 播放历史与数据持久化

### 12.1 本地历史

- 使用 IndexedDB 保存最近播放，保证接口不可用时仍能展示。
- 同一歌曲在短时间内重复播放只更新时间，不无限新增记录。
- 播放达到 30 秒或歌曲时长的 50% 时记为有效播放，取先达到者。
- 用户可清空本站历史；清空操作不声称删除网易云官方听歌记录。

### 12.2 网易云记录

- 用户主页可展示网易云返回的听歌排行和记录。
- 本站本地历史与网易云历史在界面上明确区分数据来源。

### 12.3 自定义数据库决策

P0/P1 默认不新增自有数据库，账号数据和社交写操作走网易云 API，本站设置和历史保存在本地。若需要跨设备同步、站内好友或独立评论系统，再单独设计数据库；该变更不属于本 PRD 自动授权范围。

## 13. 视觉系统

### 13.1 品牌

- 暂定英文名：`ECHOFORM`。
- 暂定中文名：`声形`。
- 品牌概念：声音获得形状。
- 左上角字标保持原站大号编辑感，但更换为新的字形与品牌进入动画。

### 13.2 字体

- 品牌与英文 UI：`Instrument Sans` 或经授权的同类无衬线字体。
- 中文 UI：`Noto Sans SC`。
- 歌词强调：`Noto Serif SC`，仅用于当前歌词和情绪文本。
- 正文移动端不小于 16px；辅助标签不小于 12px。
- 不使用随视口宽度连续缩放的字体尺寸，使用明确断点。

### 13.3 形状与表面

- 封面保持直角或最多 4px 圆角。
- 页面区块不包装成浮动卡片。
- 卡片仅用于歌单、专辑等真实重复内容。
- 不使用卡片套卡片。
- 不使用装饰性渐变球、光斑和大面积毛玻璃。

### 13.4 图标

- 使用统一的 Lucide 线性图标。
- 同一层级保持统一尺寸和线宽。
- 熟悉操作使用图标，陌生操作提供文字或提示。
- 不使用 Emoji 作为功能图标。

## 14. 动效系统

### 14.1 动效级别

| 级别 | 时长 | 场景 |
| --- | --- | --- |
| Micro | 150-250ms | 按钮、播放状态、喜欢、标签切换 |
| Page | 350-600ms | 搜索进入、抽屉、普通路由 |
| Immersive | 900-1600ms | 首页首次入场、封面展开 |
| Exit | 约 500ms | 歌曲预览退出和内容裁切离场 |

### 14.2 动效规则

- 只动画 `transform`、`opacity` 和 WebGL shader 参数，避免动画 width、height、top、left。
- 进入使用减速，退出比进入更快。
- 页面路由保持方向一致，返回恢复来源状态。
- 所有动画可被用户输入打断。
- `prefers-reduced-motion` 下保留状态顺序，改为短透明度与位移过渡。
- 动画期间不禁用播放、返回或暂停等关键操作。

- 390px：小屏手机。
- 768px：平板或窄屏。
- 1024px：桌面功能布局切换点。

- 首页画廊显示约 3-5 张窄封面，不依赖 hover。
- 预览舞台提供明确返回按钮，不能只依赖滚轮退出。
- 完整播放页按“封面、信息、控制、歌词”纵向排列。
- 评论与队列使用底部 Sheet 或整页标签，不与歌词并列。
- 底部迷你播放器与导航预留安全区，不遮挡列表末项。
- 所有触摸操作区域至少 44x44px，交互间距至少 8px。

## 16. 可访问性

- 普通正文与背景对比度至少 4.5:1。
- 键盘可完成搜索、播放控制、歌词跳转、评论抽屉和退出操作。
- 焦点顺序与视觉顺序一致，焦点样式不可移除。
- 图标按钮具有 `aria-label`。
- 当前播放、选中标签和播放模式不仅依赖颜色表达。
- 动态状态和错误通过适当的 `aria-live` 通知，但不抢夺焦点。
- 封面提供有意义的歌曲与专辑替代文本。
- 模态层打开时管理焦点，关闭后焦点返回触发入口。

## 17. 性能要求

- 只预加载当前封面及前后各 2-3 张封面。
- 图片通过尺寸参数请求合适分辨率，并声明稳定宽高比。
- Three.js 和完整播放页按路由或场景动态加载。
- WebGL 每帧逻辑预算目标小于 16ms。
- 列表超过 50 项时虚拟化或分页。
- 搜索输入防抖，滚轮和指针处理节流。
- 页面切后台后降低或暂停非必要渲染，但音频按浏览器策略继续。
- 低性能或不支持 WebGL 时回退 DOM 画廊，不阻断核心播放功能。

## 18. 版权、隐私与风险

### 18.1 版权

- 项目仅用于学习和毕业设计展示，不用于商业服务。
- 不下载、破解或重新分发受限音乐。
- 不绕过 VIP、版权和地区限制。
- 答辩演示准备少量自有或明确授权音频。

### 18.2 隐私

- 不收集网易云密码、手机验证码或二维码确认信息。
- 不在日志中记录 cookie、token、完整二维码内容或用户隐私字段。
- 用户退出后清理账号缓存。
- 分享页面只展示公开允许的数据。

### 18.3 主要风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| API 仓库已归档 | 接口随时失效 | 固定版本、适配层、本地演示数据 |
| IP 风控或 301/503 | 登录和数据请求失败 | 限流、缓存、时间戳、明确重试 |
| VIP/版权限制 | 歌曲 URL 为空 | 可用性状态、禁用播放、自动下一首 |
| 音频跨域 | 无法读取真实频谱 | 先验证 CORS；失败使用程序化音乐呼吸 |
| WebGL 性能不足 | 页面卡顿或空白 | 降低质量、暂停背景渲染、DOM 回退 |
| 功能范围过大 | 毕设无法按时完成 | 严格按 P0、P1、P2 分期 |
| 外部数据变更 | 字段解析错误 | Provider 归一化、契约测试、错误回退 |

## 22. 当前已确定决策

- ECHOFORM / 声形是当前开发与毕业设计交付使用的正式品牌名；未来改名属于大需求。
- 首页核心内容为登录用户的网易云每日推荐歌曲。
- 右上角账户入口扫码登录，成功后替换为头像。
- 搜索是一级功能，桌面和移动端均位于右上角账户入口左侧。
- 音乐库保留 `/library` 功能路由，但不常驻全局导航；登录后从个人主页或账户菜单进入。
- 首页画廊有限且不无限循环。
- 歌曲预览保留滚轮退出；完整播放页不使用滚轮退出。
- 评论和队列共用抽屉，不常驻主画面。
- 网易云 API 必须位于 `MusicProvider` 适配层之后。
- 第一版不建设站内好友系统和自有数据库。
- 登录后的沉浸页面默认使用 `ARTWORK`；游客、API 故障和 Demo Mode 使用 `INK`；
  `PAPER` 只由用户手动选择。
- 搜索输入防抖统一为 300ms；旧请求必须取消或按 revision 忽略。
- 歌曲预览进入目标约 1100ms、上限 1600ms，并且全程可中断。
- 用户手动浏览歌词后暂停自动跟随 5 秒。
- 未登录首页只显示已验证可播的“公开精选”；搜索保留可发现结果并明确可播放状态，不能承诺网易云全曲库匿名可播。
- 用户主页使用头像共享元素，不使用全屏圆形遮罩。
- Demo Mode 只能由用户显式选择，Real 请求失败不能自动切换。
- Sleep Timer 最后 3 秒使用临时输出增益渐弱，刷新后清除且不改变用户保存音量。
