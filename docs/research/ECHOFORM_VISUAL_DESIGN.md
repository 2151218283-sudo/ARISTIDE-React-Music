## 1. 文档目的

本文档把 ECHOFORM 的品牌调性、视觉语言和交互气质转化为后续 Coding 可直接执行的规则。它不是效果图合集，也不是某个页面的临时样式说明，而是产品视觉实现的统一约束。

后续新增页面或组件时，应按以下顺序决策：

1. 先确认功能在 PRD 中的产品角色和信息优先级。
2. 再选择本文定义的布局、Semantic Token 和公共组件。
3. 最后才允许添加页面特有视觉；页面特有规则不得破坏全局层级。
4. 若本文与组件规格冲突，先更新本文或对应组件规格，再修改代码。

本文不修改当前复刻站功能。现有 Aristide 复刻是交互原型和动态资产，不是最终音乐产品的完整视觉模板。

## 2. 核心视觉命题

### 2.1 一句话方向

> 编辑感音乐展览 + 专辑色彩系统 + 克制的生成式动态。

ECHOFORM 不应表现为“有很多音乐功能的后台界面”，也不应表现为“套着播放器按钮的视觉艺术实验”。它必须同时满足两件事：

- 浏览音乐时，像进入一场每天只为当前用户布置的展览。
- 真正播放、搜索、管理歌单和阅读评论时，仍然清楚、快速、可预测。

### 2.2 品牌行为句

> 浏览时，用户推动音乐；播放时，音乐推动画面。

这句话是动效取舍的最高规则：

- 用户滚动画廊时，画面运动必须直接来自用户输入和真实轨道速度。
- 音乐播放后，动态可以受播放、缓冲、节奏或音频特征驱动。
- 搜索、设置、评论、歌单编辑等任务页面不持续播放装饰动画。
- 没有输入、播放或状态变化时，界面保持安静。

### 2.3 设计关键词

| 关键词 | 在 ECHOFORM 中的含义 | 视觉表现 | 禁止误读 |
| --- | --- | --- | --- |
| 编辑感 Editorial | 内容像被策展，而不是被堆放 | 强排版、清晰编号、细分隔线、留白 | 不是报纸仿古风 |
| 沉浸 Immersive | 视线聚焦当前音乐，空间连续 | 全屏画廊、共享元素、低干扰控制 | 不是隐藏关键功能 |
| 私人化 Personal | 每日推荐和用户品味决定界面内容 | 日推序列、用户头像、封面主题色 | 不是在页面堆用户数据 |
| 动态 Kinetic | 运动表达输入、播放与层级变化 | 有限轨道波浪、歌词同步、状态呼吸 | 不是所有元素持续漂浮 |
| 有触感 Tactile | 输入有即时且可控的反馈 | 惯性、按压、拖动跟手、边界明确 | 不是夸张弹跳和拟物阴影 |
| 克制 Quiet | 非当前信息主动退后 | 低对比次级内容、无厚重容器 | 不是低对比到不可读 |
| 色彩驱动 Chromatic | 当前音乐封面决定局部氛围 | ARTWORK 主题、平面颜色过渡 | 不是固定紫蓝渐变 |
| 精确 Precise | 状态、位置、计时和控制可信 | 对齐、稳定尺寸、数字等宽、可见焦点 | 不是冷漠或机械化 |

### 2.4 视觉性格比例

| 维度 | 比例 | 说明 |
| --- | ---: | --- |
| 内容与装饰 | 85 / 15 | 封面、歌名、歌词是内容；粒子和背景只做状态反馈 |
| 安静与运动 | 70 / 30 | 大多数时间稳定，只在输入和状态变化时运动 |
| 编辑与工具 | 60 / 40 | 首页偏编辑展览，搜索和管理页偏高效工具 |
| 中性与彩色 | 75 / 25 | 中性空间承载内容，封面色只在关键区域出现 |
| 平面与层叠 | 80 / 20 | 主要靠排版和分隔线，抽屉与对话框才使用层叠 |

## 3. 优秀产品参考与取舍

本节用于说明设计依据，不能作为逐像素复制清单。参考界面核对日期为 2026-07-29。

| 参考 | 借鉴内容 | ECHOFORM 的转化 | 明确不复制 |
| --- | --- | --- | --- |
| [Aristide Benoist](https://aristidebenoist.com/) | 有限胶片轨道、速度波浪、共享空间展开、滚轮退出 | 首页日推画廊、歌曲预览舞台、自然回到原位置 | 项目作品集文案、外链逻辑、全部窄竖图比例 |
| [Apple Music](https://music.apple.com/us/new) | 导航、内容画布、持久播放器三层清晰；封面与播放操作紧密 | 固定导航和播放基线不与主内容争抢；歌曲随处可播放 | 侧栏结构、浅色卡片密度、营销横幅 |
| [NTS](https://www.nts.live/) | 高对比编辑排版、细线分区、直播播放状态持续可见 | 强化编号、上下文标题、无卡片播放基线和队列层级 | 过高的信息密度、粗粝媒体视觉、直播电台结构 |
| [Endel](https://endel.io/) | 生成式视觉明确服务声音状态；非播放任务保持简洁 | 完整播放页用音频状态驱动背景，搜索与音乐库保持安静 | 营销式首页、大面积发光按钮、模糊光晕装饰 |
| [Spotify Design](https://spotify.design/) | 播放器、队列和多设备的一致组件体系 | 播放状态由单一全局内核驱动，组件只消费统一状态 | 绿色品牌色、圆角卡片海、桌面客户端布局照搬 |
| [SoundCloud](https://soundcloud.com/) | 波形同时表达内容、进度和可拖动位置 | ProgressRail 可在完整播放页升级为可访问波形 | 社交流信息流、橙色品牌表达、把波形当装饰 |
| [TIDAL](https://tidal.com/) | 近黑空间、高清封面和音质信息的层级 | INK 主题和音质状态采用低噪声表达 | 奢华黑金语气、订阅营销结构 |

研究结论：ECHOFORM 最值得保留的差异不是某种配色，而是“空间连续性”。封面从画廊、歌曲预览到完整播放页必须被用户理解为同一个对象，而不是三张重新出现的图片。

## 4. 品牌身份

### 4.1 名称解释

- `ECHO`：声音的回响、记忆和再次被听见。
- `FORM`：声音通过封面、歌词、颜色和运动获得形态。
- `声形`：中文辅助名，用于品牌说明、About 和答辩材料，不与英文主标并列塞入窄导航。

### 4.2 品牌标志

第一版使用文字标志 `ECHOFORM`，不先制作复杂图形 Logo。原因是当前产品最强的品牌资产是画廊和动态，图形标志不应与封面争抢。

规则：

- 主标始终使用全大写 `ECHOFORM`。
- 标志字间距为 `0`，通过字体本身和字重建立识别，不使用负字距。
- 运行时导航品牌使用正常宽度的 `--ef-font-body` 粗体字形，不复用原站高度压缩的 `TNY` 展示字体，也不使用横向缩放补偿。
- 桌面首页位于左上角，无胶囊、底板或外框。
- 移动端缩小字级，但保留完整名称，不压缩成 `EF`。
- 二维码入口使用独立的 `BrandMark` 图形按钮；登录后同一位置替换为真实头像。
- 网易云 Logo 只用于说明登录来源，不作为 ECHOFORM 主品牌，不擅自重绘或变形。

### 4.3 品牌语言

界面文案应短、具体、像展览标签，不写营销口号或解释功能的长句。

| 场景 | 推荐 | 避免 |
| --- | --- | --- |
| 首页上下文 | `DAILY SIGNAL · JUL 29` | `为你推荐的专属好音乐` |
| 播放状态 | `PLAYING`、`BUFFERING` | `正在为您努力加载歌曲` |
| 空状态 | `今天的推荐暂时不可用` | `空空如也，快去探索吧` |
| 恢复动作 | `重试`、`使用演示数据` | `我知道了` |
| 版权错误 | `当前地区不可播放` | `播放失败` |

## 5. 视觉原则

### 5.1 内容是唯一主角

- 首页主角是每日推荐封面，不是欢迎语和功能介绍。
- 完整播放页主角是当前封面与歌词，不是频谱装饰。
- 用户主页主角是头像、音乐品味和歌单，不是统计卡片。
- 任何背景动态不得降低歌名、歌词、控制和错误信息的可读性。

### 5.2 一页一个主要运动

| 页面 | 唯一主要运动 |
| --- | --- |
| 首页 | 有限画廊的横向移动和速度波浪 |
| 歌曲预览 | 封面共享空间展开与收缩 |
| 完整播放页 | 歌词纵向同步和轻量声音呼吸 |
| 用户主页 | 头像进入与内容层级展开 |
| 搜索 | 搜索框展开及结果交叉淡入 |
| 音乐库 / 歌单 | 常规纵向滚动，无持续装饰动画 |
| 设置 | 状态切换微动效，无页面背景运动 |

### 5.3 沉浸不等于不可发现

- 播放、暂停、退出和搜索始终有可见入口。
- 滚轮退出歌曲预览必须同时提供可点击返回控制和 `Escape`。
- 手势不能是完成关键任务的唯一方式。
- 控件在静止时可以降权，但不能完全消失。

### 5.4 色彩来自音乐，不覆盖音乐

- 中性底色建立稳定品牌识别。
- 当前封面的主色只用于局部表面、进度、选中态或完整播放页背景。
- 系统错误、警告、成功颜色不被封面主题替换。
- 禁止固定紫蓝渐变、光球、Bokeh、霓虹外发光和随机彩色阴影。

### 5.5 容器只在需要边界时出现

- 页面区块使用留白、网格和分隔线，不包装成浮动卡片。
- 卡片只用于重复内容项、对话框、抽屉内的独立对象。
- 禁止卡片嵌套卡片。
- 卡片圆角不超过 8px；画廊封面和大封面默认无圆角或仅 2px 防锯齿圆角。

## 6. Token 架构

### 6.1 三层模型

```text
Primitive Token（原始值）
        ↓
Semantic Token（界面含义与主题映射）
        ↓
Component Token（组件局部契约）
```

约束：

- Raw 色值只允许出现在 Primitive Token 定义中。
- 页面和组件禁止直接引用 Primitive 色彩 Token。
- 普通组件优先引用 Semantic Token；只有形成稳定复用边界后才建立 Component Token。
- 运行时专辑颜色通过受控 CSS 自定义属性注入，不进入静态色板。
- Token 集中定义在 `src/app/globals.css`；CSS Modules 负责组件布局、局部状态和动画组合。
- Tailwind CSS 4 只映射 Semantic Token，不复制一套独立颜色。

### 6.2 命名规则

```text
Primitive:  --ef-{category}-{family}-{step}
Semantic:   --ef-{meaning}-{role}-{state}
Component:  --ef-{component}-{property}-{state}
Runtime:    --ef-artwork-{role}
```

示例：

```css
--ef-color-ink-950: /* primitive */;
--ef-surface-canvas: var(--ef-color-ink-950);
--ef-player-progress-track: var(--ef-border-subtle);
--ef-player-progress-fill: var(--ef-action-playing);
```

同一图层内不得用临时超大 `z-index` 解决遮挡。先确认元素是否属于正确层级。

## 8. Semantic Token 与主题

### 8.1 三种主题

| 主题 | 角色 | 默认页面 | 规则 |
| --- | --- | --- | --- |
| `INK` | 稳定深色基线 | 游客首页、API 降级、Demo Mode、深色偏好 | 强调封面亮度和夜间沉浸 |
| `PAPER` | 编辑式浅色基线 | 用户手动选择 | 强调排版、列表和长时间阅读，不按路由强制切换 |
| `ARTWORK` | 封面自适应主题 | 登录后首页、歌曲预览、完整播放页 | 默认主题，提取失败回退 INK |

主题通过根节点 `data-theme="ink | paper | artwork"` 切换。禁止组件自行判断深浅模式并写私有色值。
登录后的沉浸页面默认进入 `ARTWORK`。游客、API 故障和显式 Demo Mode 使用 `INK`；
`PAPER` 只能由用户主动选择，搜索、音乐库和设置路由不得擅自覆盖当前主题偏好。

### 8.2 Semantic 颜色

| Semantic Token | INK | PAPER | ARTWORK |
| --- | --- | --- | --- |
| `--ef-surface-canvas` | `ink-950` | `paper-50` | 受控 `artwork-surface` |
| `--ef-surface-raised` | `ink-900` | `paper-100` | 由画布向可读中性色收敛 |
| `--ef-surface-overlay` | `ink-800` | `paper-50` | 始终保证前景对比 |
| `--ef-text-primary` | `chalk-300` | `ink-950` | 自动选择可读前景 |
| `--ef-text-secondary` | `smoke-500` | `smoke-600` | 自动计算后的次级前景 |
| `--ef-text-disabled` | 主文字 42% | 主文字 38% | 主文字 42% |
| `--ef-border-subtle` | 主文字 16% | 主文字 18% | 当前前景 18% |
| `--ef-border-strong` | 主文字 36% | 主文字 38% | 当前前景 40% |
| `--ef-action-primary` | `phosphor-400` | `ink-950` | 可读的封面强调色或前景 |
| `--ef-action-playing` | `signal-dark` | `signal-light` | 选择与实际画布至少 3:1 的信号色 |
| `--ef-focus-ring` | `phosphor-400` | `ink-950` | 与当前画布至少 3:1 |
| `--ef-status-success` | `success-dark` | `success-light` | 按前景模式选择 |
| `--ef-status-warning` | `warning-dark` | `warning-light` | 按前景模式选择 |
| `--ef-status-error` | `error-dark` | `error-light` | 按前景模式选择 |
| `--ef-status-info` | `info-dark` | `info-light` | 按前景模式选择 |

表中的短名称均指向 `--ef-color-*` Primitive Token，不允许在组件中直接使用。

### 8.3 ARTWORK 主题算法

输入：当前歌曲的 1:1 封面位图。输出以下运行时变量：

```css
--ef-artwork-primary: /* 主色 */;
--ef-artwork-secondary: /* 次色 */;
--ef-artwork-surface: /* 受控画布色 */;
--ef-artwork-on-surface: /* 可读前景 */;
--ef-artwork-on-surface-muted: /* 可读次级前景 */;
```

处理规则：

1. 以缩小后的封面采样，避免在主线程读取完整大图。
2. 忽略透明像素、接近纯黑和纯白且占比过低的异常点。
3. 主色用于画布时降低饱和度并限制亮度，不能直接铺满原始高饱和颜色。
4. 根据最终画布计算前景；普通文字对比度至少 4.5:1，图标和焦点至少 3:1。
5. 若主色无法同时满足品牌克制和对比度，使用中性画布，仅把主色用于进度和局部选中态。
6. 色彩切换使用平面颜色插值，不使用固定渐变。
7. 图片跨域、提取异常或超时时立即回退 `INK`，界面不得闪成浏览器默认白色。
8. 切歌时旧主题保留到新封面与颜色均准备完成，再一次性交叉过渡。

## 11. 封面与媒体规范

### 11.1 AlbumArtwork

- 所有音乐封面数据源使用 1:1 原图。
- 浏览态画廊将方形封面裁成窄竖切片，使用中心裁切或已配置焦点，不拉伸像素。
- 聚焦和展开时逐步恢复完整 1:1 封面，用户能理解它与原切片是同一对象。
- 封面从浏览态到预览态使用同一纹理和几何对象，避免先消失再换图。
- 列表封面固定尺寸，加载失败不能导致行高变化。
- 非首屏封面使用响应式图片和延迟加载；明确 `width`、`height` 或 `aspect-ratio`。
- 有意义的封面 Alt 使用“歌曲名 - 艺术家封面”；纯背景复制图使用空 Alt。

### 11.2 尺寸

| Variant | Desktop | Tablet | Mobile |
| --- | ---: | ---: | ---: |
| `film-slice` | 约 7.8vw × 46.3vh | 56px × 280px | 35px × 165px |
| `track-row` | 48px | 48px | 48px |
| `queue-row` | 40px | 40px | 44px |
| `playlist-tile` | 容器 1:1 | 容器 1:1 | 容器 1:1 |
| `preview-focus` | min(42vw, 560px) | min(62vw, 480px) | calc(100vw - 32px) |
| `player-focus` | min(38vw, 520px) | min(54vw, 440px) | min(72vw, 300px) |

`film-slice` 是唯一允许使用视口比例控制场景几何的组件；字体仍不得使用视口连续缩放。

### 11.3 媒体状态

| 状态 | 表现 |
| --- | --- |
| Loading | 与最终封面同尺寸的低对比静态底板，准备超过 300ms 后开始轻呼吸 |
| Loaded | 160ms 不透明度进入，不改变布局 |
| Error | 中性底板 + 唱片图标 + 可读替代文字，不显示破图图标 |
| Checking | 搜索结果首次点播或“仅看可播放”筛选期间，保留行内容与播放控件位置，在图标区域显示短暂进度；不得把它画成已播放或不可播放 |
| Verified playable | 不增加装饰徽章；正常可用的播放图标即为唯一正向信号，避免列表噪声 |
| Unavailable | 保留封面，叠加低对比遮罩和“不可播放”文本 |
| Playing | 仅在需要区分时显示播放标记，不能覆盖标题主体 |

## 12. 图标与控制形状

- 统一使用 Lucide 风格线性图标；同层级描边宽度保持一致。
- 不使用 Emoji 作为功能图标。
- 熟悉命令优先使用图标：播放、暂停、上一首、下一首、音量、搜索、关闭、返回、收藏、下载。
- 陌生或低频图标必须有 Tooltip；所有图标按钮有可访问名称。
- 可见图标常用 18px 或 20px，触控区域至少 44×44px。
- 播放 / 暂停是少数允许使用实心图形的控制，用来形成主次层级。
- 文本按钮只用于清楚的命令：`重试`、`登录`、`使用演示数据`、`查看全部`。
- 不用带文字的圆角矩形代替已有通用符号，例如不用“关闭”文字胶囊代替关闭图标。

## 13. 组件复用总则

### 13.1 组件状态模型

交互状态优先级：

```text
disabled > loading > pressed > focus-visible > hover > default
```

`selected`、`playing`、`error` 是语义变体，可与上述交互状态组合，但不得仅靠颜色表达。

歌曲可用性是独立语义：`checking`、`verified-playable`、`unavailable`、`unknown`。首页画廊只接收
`verified-playable` 曲目；搜索列表可显示其余状态，但未知状态不得使用可播放的强调色或播放中图形。

所有交互组件必须实现：

- `default`
- `hover`（仅支持 Hover 的设备）
- `pressed`
- `focus-visible`
- `disabled`
- `loading`（存在异步行为时）
- 对应语义状态，如 `selected`、`playing`、`error`

状态切换不得改变组件外框尺寸。Hover 不移动相邻内容，Pressed 缩放最多到 0.97 且只作用于自身视觉层。

### 13.2 复用边界

- 页面不得复制公共按钮、输入框、封面、曲目行、抽屉和状态视图样式。
- 数据结构不同但视觉和交互相同，应通过 Props 扩展已有组件。
- 只有布局、语义和状态模型都不同，才允许新建组件。
- 公共组件不读取网易云原始字段，只接收 `MusicProvider` 适配后的内部模型。
- 页面负责数据请求和组合；基础组件不发起页面级网络请求。

## 14. 核心组件规格

### 14.1 AppShell

**用途**：统一主题、导航、播放器、图层和安全区。

**禁用**：不得在页面内部嵌套第二个 AppShell。

- Variants：`immersive-fixed`、`player-immersive`、`content-scroll`。
- Desktop 最小高度为 `100dvh`，固定模式 `overflow: hidden`。
- Mobile 为顶部和底部固定元素写入内容 Insets。
- 主题切换挂在根节点，路由切换不卸载全局 Audio Provider。
- 入口提供 Skip Link；路由切换后焦点移到主内容标题。

### 14.2 FixedNavigation

**用途**：品牌、当前上下文、搜索、账号入口。

**禁用**：不承载播放控制和页面内全部操作。

- Desktop：左上品牌，中上上下文，右上搜索与头像；无可见容器。
- Mobile：顶部保留品牌、搜索和头像；不设置常驻底部一级导航。
- 中上上下文只用于定位，不作为重复页面入口；移动端空间不足时可以隐藏上下文。
- 音乐库保留为个人空间功能，从用户主页或账户菜单进入，不常驻全局导航。
- 图标触控区域至少 44×44px，入口间隔至少 8px。
- 沉浸页无操作时次级入口降至较低对比，但 Focus 或指针移动时立即恢复。

### 14.3 BrandMark

**用途**：未登录账号入口、加载品牌占位。

**禁用**：不作为任意页面装饰水印。

- 视觉尺寸 24px，交互尺寸 44px。
- 未登录显示 ECHOFORM 独立符号或简化声形标记；点击打开 QR Dialog。
- Loading 使用轻量旋转弧线，不能让标志持续旋转。
- 登录成功后在同一边界内转换为 AvatarButton，保持空间连续。

### 14.4 IconButton

**用途**：标准媒体命令和紧凑工具。

**禁用**：不用于陌生的业务动作而缺少文字解释。

- Sizes：`sm` 36px（仅桌面低频）、`md` 44px、`lg` 52px。
- 图标分别为 16px、18px、22px。
- Default 无底板；Hover 使用低对比状态层；Pressed 轻微缩放。
- Focus 使用双层 2px 可见焦点环，不移除 Outline 而无替代。
- Loading 在原图标区域显示进度，不改变按钮宽度。
- Tooltip 延迟 500ms 出现，键盘 Focus 时立即可见。

### 14.5 TextButton

**用途**：重试、确认、查看全部等明确命令。

**禁用**：不用于播放、关闭、音量等已有通用符号。

- Heights：40px Desktop，44px Mobile。
- Variants：`primary`、`secondary`、`quiet`、`danger`。
- 最大圆角使用 `radius-md`，不使用胶囊形。
- Loading 保留原文字宽度，显示前置小进度并设置 `aria-busy`。
- `danger` 与普通操作保持空间分离，不放在连续按钮组中间。

### 14.6 AvatarButton

**用途**：登录用户主页入口和账号状态。

**禁用**：不使用装饰头像或随机渐变头像冒充用户资料。

- 视觉头像 32px Desktop、36px Mobile，交互区至少 44px。
- 图片保持圆形 1:1；加载失败显示用户昵称首字母和中性底色。
- 新通知使用小点加可访问文本，不仅用红点。
- 点击进入本地 `/profile/[id]`，头像作为共享元素扩展到主页头部。

### 14.7 SearchField

**用途**：按歌曲、歌手、专辑关键词搜索。

**禁用**：不使用仅有 Placeholder 而无可访问 Label 的输入框。

- Collapsed：导航中的搜索图标和文本入口。
- Expanded Desktop：高度 48px，最大宽度 720px；Mobile：宽度占可用内容区，高度 48px。
- 搜索图标位于前部，清除按钮位于末端；清除按钮只在有值时出现。
- 输入防抖 300ms；加载不清空旧结果，在输入尾部显示小进度。
- `Escape` 第一次清空建议或关闭结果层，第二次收起搜索。
- Error 在字段下内联显示原因和重试，设置 `aria-invalid` 与关联描述。

### 14.8 SegmentedTabs

**用途**：搜索分类、评论 / 队列、音乐库分类。

**禁用**：不用于二元设置，二元设置使用 Switch。

- 标签数量 2-4 个；更多分类使用横向可滚动 Tab，而不挤压文字。
- 高度 40px Desktop、44px Mobile。
- 选中态使用底部线、字重和 `aria-selected`，不使用填满的胶囊背景。
- 切换内容使用短交叉淡入；布局高度不同不得造成标题跳动。

### 14.9 AlbumArtwork

**用途**：统一呈现歌曲、专辑、歌单媒体。

**禁用**：不在组件内部直接请求高清图或决定页面主题。

- Variants：`film-slice`、`thumbnail`、`tile`、`preview`、`player`。
- `film-slice` 与展开态共享纹理标识和焦点数据。
- Hover 只提升亮度和轻微深度，不添加悬浮文字卡片。
- Selected 附加可读标记；Playing 可使用局部进度或播放图标。
- Error 和 Loading 保持固定 `aspect-ratio`，防止 CLS。

### 14.10 TrackRow

**用途**：搜索结果、专辑曲目、歌单、历史。

**禁用**：不用于首页主画廊。

- Desktop 高度 64px，Mobile 最小 68px。
- Anatomy：序号 / 封面、歌曲信息、专辑、时长、溢出操作。
- 小屏只保留封面、歌曲、艺术家和溢出操作；专辑与时长按优先级折叠。
- Hover 显示播放动作但保留序号占位，不导致列位移。
- Playing 同时显示播放标记、`PLAYING` 屏幕阅读文本和强调色。
- 不可播放行降低视觉权重并显示原因；不能只禁用无解释。

### 14.11 PlayerTransport

**用途**：播放 / 暂停、上一首、下一首、模式。

**禁用**：不重复创建独立 Audio 实例。

- 主播放按钮 52px Desktop、48px Mobile；相邻控制至少 44px。
- 中央顺序固定，页面切换不重排播放 / 暂停位置。
- Buffering 在播放按钮中显示局部环形进度，保留当前播放图标语义。
- Shuffle、Repeat 使用图标状态和可访问文本；单曲循环显示数字标识。
- 在队列首尾禁用不可用的上一首或下一首，并提供 Tooltip 原因。

### 14.12 ProgressRail

**用途**：显示播放、缓冲和拖动位置。

**禁用**：不把纯装饰频谱伪装成可拖动进度。

- Desktop 可见轨道 2px，交互命中高度至少 24px；Mobile 命中高度至少 44px。
- 三层：底轨、Buffered、Played；Played 使用 `action-playing`。
- 拖动时显示时间预览，释放后更新音频；键盘支持方向键微调。
- 使用线性时间映射，不能给真实进度加缓动延迟。
- 波形 Variant 只在有可靠采样数据时启用；仍需暴露原生 Slider 语义。

### 14.13 VolumeControl

**用途**：桌面音量和静音。

**禁用**：移动端不复制系统音量控制，除非浏览器确实支持且产品有充分理由。

- Desktop：音量图标 44px + 96px Slider。
- Slider 支持鼠标、触控和键盘；显示 0-100 的可访问值。
- 静音不丢失上次非零音量，再次点击恢复。
- 小屏默认只显示静音入口或完全交给系统音量。

### 14.14 LyricsViewport

**用途**：同步歌词、逐字歌词和手动定位。

**禁用**：不作为普通文章阅读器复用。

- 当前行位于视觉中心附近，前后行逐级降权但仍可读。
- 自动滚动只在当前行越过稳定区时发生，避免每行都微调屏幕。
- 用户手动滚动后暂停自动跟随 5 秒，并显示“回到当前歌词”控制。
- 点击歌词定位播放时必须有即时反馈，并受歌曲是否可 Seek 限制。
- 逐字高亮只使用前景填充变化，不给每个字添加位移动画。
- 无歌词时切换到 StatusView，不保留空白滚动容器。

### 14.15 CommentItem

**用途**：歌曲评论、回复和点赞。

**禁用**：不承载聊天或站内好友动态。

- Anatomy：头像、昵称、时间、正文、点赞、回复入口。
- 正文 16px 起，长内容正常换行；时间和点赞是次级信息。
- 热门标记使用文字或图标加文字，不只用颜色。
- 回复通过层级线和缩进表达，移动端最大缩进一级，避免内容过窄。
- 删除或提交失败在该评论位置内联显示，不只发 Toast。

### 14.16 QueueRow

**用途**：当前播放队列和拖动排序。

**禁用**：不作为永久歌单编辑器。

- 高度 56px Desktop、60px Mobile。
- 当前项有 Playing 标记；即将播放项保持中性。
- 拖动把手至少 44px 命中，必须提供键盘“上移 / 下移”替代。
- 移除动作可撤销，Toast 提供“撤销”。
- 队列超过 50 项时使用虚拟列表或分段渲染。

### 14.17 Drawer

**用途**：桌面评论 / 队列的次级工作区。

**禁用**：不用于一级页面导航或完整用户主页。

- 从触发控制所在侧进入，宽度 400-480px，最大不超过视口 42%。
- Header 固定，内容单独滚动，Footer 仅在确有固定提交动作时出现。
- 评论和队列通过 SegmentedTabs 共用容器，不叠加第二层 Card。
- 打开后焦点进入标题或首个控件；关闭后返回触发按钮。
- `Escape` 关闭；背景是否可交互由任务决定，但不能形成两个同时滚动区域。

### 14.18 BottomSheet

**用途**：移动端评论、队列、更多操作。

**禁用**：不承载必须深链接的完整页面。

- 初始高度约 68dvh，可扩展到安全区内全高。
- 顶部有拖动把手和明确关闭按钮；下滑不是唯一关闭方式。
- 弹出时锁定背景滚动，关闭后恢复原页面位置。
- 输入评论时适配软键盘，不让提交按钮被遮挡。

### 14.19 Dialog

**用途**：二维码登录、确认、需要明确阻断的错误。

**禁用**：不用于主要导航和普通详情浏览。

- Desktop 最大宽度 480px；Mobile 宽度为可用视口减 32px。
- 最大圆角 8px，背景使用 `surface-overlay`，Scrim 让背景退后但不装饰性模糊。
- 必须有标题、关闭按钮和可预测的 `Escape` 行为。
- QR 登录内容保持稳定尺寸，状态更新不改变 Dialog 外框。
- 打开时焦点进入，关闭后回到原入口；使用 `aria-modal` 和正确标题关联。

### 14.20 Toast

**用途**：短暂成功、可撤销动作、非阻断提醒。

**禁用**：不作为持续错误、表单错误或不可播放原因的唯一载体。

- Desktop 位于右下且避开 Player；Mobile 位于迷你播放器和底栏上方。
- 一次最多堆叠 3 条；同类消息合并。
- 默认 4 秒消失，重要可撤销消息 5 秒。
- Success、Info 使用 `aria-live="polite"`；严重错误使用内联区域处理。
- 有动作时只允许一个短命令，例如“撤销”。

### 14.21 StatusView

**用途**：空数据、页面级错误、不可播放、离线。

**禁用**：不在正常数据之间插入巨大的宣传式空状态。

- Anatomy：状态图标、单句标题、最多两行原因、一个主恢复动作、可选次操作。
- 不使用装饰性插画和 Emoji。
- Page Variant 居中但不占满整屏；Inline Variant 与目标内容对齐。
- 状态图标、文字和动作共同表达语义，不只变色。

### 14.22 Skeleton

**用途**：超过 300ms 且最终布局可预测的加载。

**禁用**：不为瞬时图标状态创建整页骨架。

- 尺寸必须与最终内容一致。
- 使用低对比呼吸，不使用横向扫光渐变。
- 动画周期不短于 1200ms；Reduced Motion 下静止。
- 文字骨架只显示 2-3 个合理长度，不模拟每个字符。

### 14.23 PlaylistTile

**用途**：音乐库、用户主页、推荐歌单。

**禁用**：不用于单曲搜索结果。

- 1:1 封面，上方媒体、下方名称和作者；整个区块不再放入外层 Card。
- Hover 显示 Play IconButton，但不把封面整体放大到挤压网格。
- Selected / Playing 有额外标记和可访问文本。
- Grid 最小列宽 160px Desktop、136px Tablet；Mobile 2 列并保证文字不溢出。

## 15. 关键交互动效

### 15.1 通用动效规则

- 只动画 `transform`、`opacity` 和受控 Shader 参数；颜色使用 CSS 插值。
- 不动画 `width`、`height`、`top`、`left` 造成布局重排。
- 进入使用减速曲线，退出更快。
- 动画必须可中断；新输入接管当前目标值，而不是排队等待。
- 动画期间播放、暂停、退出等关键控制仍可操作。
- 运动元素每个页面控制在 1-2 个主要层级。
- 任何状态的首次视觉反馈在 100ms 内出现。

### 15.2 首次入场

1. 画布和固定导航先占据最终位置，避免布局跳动。
2. 品牌字形使用裁切平移进入。
3. 画廊从右侧紧凑起点扩展到中央有限轨道。
4. 封面按 30-50ms 轻微错峰出现，但总延迟有上限，不能让最后一项等待数秒。
5. 数据尚未加载时先使用同尺寸媒体占位，不显示全屏 Spinner。
6. 完整稳定目标不超过 1600ms；用户滚动时立即接管动画。

### 15.3 有限画廊滚动

- 纵向滚轮映射横向有限轨道。
- 单次输入先限幅，再插值到 Target；当前和目标都在首尾范围内 Clamp。
- 波浪由实际帧间速度驱动，包括纵向位移、纵向缩放和轻微 Z 旋转。
- 到达边界后向外输入直接丢弃，不累积位移，不产生波浪。
- 停止输入后平面回到水平静止。
- Pointer 只提供克制视差，不能让封面逃离可点击位置。

### 15.4 画廊进入歌曲预览

1. 点击命中的封面成为唯一共享元素。
2. 当前窄竖裁切沿原位置扩展并恢复完整 1:1 图像。
3. 相邻封面退到半宽辅助位置，远端保持有限顺序，不首尾相接。
4. 歌名立刻开始裁切揭示；元信息约 400ms 后进入；`EXPLORE` 约 600ms 后进入。
5. 完整进入目标约 1100ms、上限 1600ms；控制在第一帧即响应，且全程可退出。
6. 不允许封面先淡出、详情页再从中央淡入。

### 15.5 歌曲预览退出

- 任意非零滚轮事件触发退出，无阈值、无方向要求。
- 第一个滚轮事件只改变模式，不移动恢复后的画廊。
- 封面在约 500ms 内回到原轨道位置；文字同时裁切退出。
- 同一手势的后续滚轮事件允许驱动恢复后的轨道，形成连续空间感。
- `Escape`、返回按钮和项目计数触发完全相同的退出状态机。
- 完整播放页不支持滚轮退出，防止阅读歌词时误退。

### 15.6 `EXPLORE` 到完整播放页

- 目标必须是本地 `/track/[id]`，不得跳到原作品集或外部详情页。
- 预览封面继续缩放和定位到播放页封面槽位。
- 当前播放状态和进度不中断；路由变化不重建 Audio。
- 页面标题、歌词和控制在封面定位后分层进入。
- 浏览器 Back 返回预览或原画廊位置，并保持当前播放。

### 15.7 搜索展开

- 从右上搜索入口向页面中央展开，时长约 420ms。
- 输入框先可输入，结果区域后进入；不能等待展开结束才允许打字。
- 旧查询到新查询使用同容器交叉淡入，保留滚动位置只在查询未变化时成立。
- Mobile 进入独立 `/search` 页面，不从右上角拉出窄浮层。

### 15.8 QR 登录

- BrandMark 作为动效起点，Dialog 从该位置缩放和淡入，时长约 480ms。
- QR 图本身不缩放变形，始终保持清晰像素和足够静区。
- 登录成功后 Dialog 收起，BrandMark 在同一位置转换为 AvatarButton。
- 头像进入用户主页时使用约 600ms 圆形共享元素，不使用全屏圆形遮罩覆盖内容。

### 15.9 播放基线

- 首次产生播放状态后从底部进入，约 320ms。
- 路由切换时保持固定，不重复入场。
- 沉浸播放且无操作时，次要控制降低对比；Pointer、Focus 或触控后立即恢复。
- 播放 / 暂停图标在固定边界内交叉变换，不改变按钮大小。

### 15.10 歌词同步

- 当前行在 200-260ms 内改变权重、前景和轻微位置。
- 逐字歌词使用线性时间填充，与音频时间严格同步。
- 自动滚动使用短位移并保持当前行稳定区，不对每个字触发滚动。
- Buffering 时歌词停在当前时间，不做假进度。

### 15.11 Reduced Motion

`prefers-reduced-motion: reduce` 下：

- 取消画廊波浪、指针视差、大范围平移和逐字填充运动。
- 首页可使用短交叉淡入呈现有限轨道。
- 共享元素转场改为 150-220ms 的淡入淡出，但信息出现顺序不变。
- 歌词直接切换当前行权重，不自动平滑滚动。
- Skeleton 静止。
- 用户仍能通过滚轮、按钮、键盘完成所有任务。

### 15.12 运行时调度不改变视觉因果

- 画廊的连续渲染只服务于入场、用户输入、预览转场和回弹收束。稳定画面在完成最终绘制后保持静止，下一次交互先恢复绘制再反馈，不能出现首帧迟滞或位置跳变。
- 质量层级只能减少像素密度、抗锯齿和不可见计算，不能移除有限首尾边界、真实速度波浪的因果关系、预览的空间连续性或可点击区域。
- 若 Canvas 不可用或受限质量仍不能满足最低目标，使用既有 DOM 画廊。降级后信息顺序、选中态、首尾禁用状态、键盘和触控路径保持一致。
- 播放时间的窄更新只改变进度填充、计时和实际变更的歌词行/词；不得造成导航、封面、队列或页面容器的视觉抖动。

## 16. 系统状态视觉

### 16.1 状态反馈时间

| 等待时间 | 表现 |
| ---: | --- |
| 0-300ms | 保持当前状态，不闪现加载控件 |
| 300-1000ms | 在触发位置显示局部进度 |
| 超过 1000ms | 使用与最终布局同尺寸 Skeleton 或明确状态文字 |
| 超过 10s | 显示超时原因、重试和可用降级方案 |

### 16.2 首屏加载

- AppShell、导航和画廊边界立即稳定。
- 画廊使用同尺寸媒体占位，封面逐项替换，不改变位置。
- 不使用普通全屏 Spinner，也不显示“Loading...”覆盖整个展览。
- WebGL 尚未准备时保留中性画布；初始化失败则切换到可操作 DOM 封面列表或演示数据。
- 屏幕阅读器使用单一 `aria-live` 状态，不逐张播报封面加载。

### 16.3 搜索加载

- 输入和旧结果保持可用。
- 输入框末端显示小进度，结果标题显示“正在更新”。
- 新结果准备完成后交叉替换，不能先清空成空白。
- 用户改变关键词时取消旧请求或忽略过期响应。

### 16.4 音频加载与缓冲

- 首次加载在播放按钮内显示进度。
- 已播放中发生缓冲时，ProgressRail 停在真实位置，Buffered 层继续更新。
- 超过阈值显示内联“连接较慢”，并提供重试或下一首。
- 不让整页进入 Loading，也不冻结歌词和队列操作。

### 16.5 QR 登录状态

| API 状态 | 视觉 | 文案与动作 |
| --- | --- | --- |
| `801` 等待扫码 | QR 清晰显示，状态点轻呼吸 | `使用网易云音乐扫码` |
| `802` 已扫码待确认 | QR 保持，外圈显示进度 | `请在手机上确认登录` |
| `803` 登录成功 | 成功图标与头像预览，随后收起 | `登录成功`，无需额外按钮 |
| `800` 二维码过期 | QR 降权并覆盖过期状态 | `二维码已过期` + `刷新二维码` |
| 网络错误 | 保留最近 QR 边界，不显示为可用 | `无法连接登录服务` + `重试` |

### 16.6 空数据

空状态统一为“一句原因 + 一个恢复动作”，不使用装饰性插画。

| 场景 | 标题 | 主动作 |
| --- | --- | --- |
| 搜索无结果 | `没有找到相关音乐` | `修改关键词` |
| 每日推荐为空 | `今天的推荐暂时不可用` | `查看公共精选` |
| 无歌词 | `这首歌暂时没有歌词` | `返回封面视图` |
| 无评论 | `还没有可显示的评论` | P1 后为 `写下第一条评论` |
| 无历史 | `播放记录会出现在这里` | `去发现音乐` |
| 无歌单 | `还没有创建歌单` | `新建歌单` |
| 空队列 | `队列中没有下一首` | `浏览每日推荐` |
| 收藏为空 | `喜欢的音乐会保存在这里` | `去搜索` |

### 16.7 错误状态

持续错误必须内联展示，Toast 只做补充。错误文案说明“发生了什么 + 用户能做什么”。

| 错误 | 视觉位置 | 文案 | 恢复动作 |
| --- | --- | --- | --- |
| API 故障 | 页面内容区 | `音乐服务暂时不可用` | `重试`、用户显式点击 `使用演示数据` |
| 网络离线 | 顶部内联状态条 | `当前处于离线状态` | `重新连接` |
| 音源失效 | 播放控制附近 | `该音源已经失效` | `重试`、`播放下一首` |
| VIP 限制 | 曲目行和播放器 | `该歌曲需要相应会员权限` | `查看其他版本` |
| 地区限制 | 曲目行和播放器 | `当前地区不可播放` | `播放下一首` |
| 版权下架 | 曲目行和播放器 | `歌曲因版权原因不可用` | `返回列表` |
| 歌词失败 | LyricsViewport | `歌词加载失败` | `重试` |
| 评论失败 | 评论区域 | `评论加载失败` | `重试` |
| 登录失效 | 账号相关操作处 | `登录状态已失效` | `重新扫码登录` |

错误发生时：

- 不清除仍然有效的旧数据。
- 不把所有错误都转换成“未知错误”。
- Error 色必须同时配图标或文字。
- 重试按钮在请求中进入 Loading，防止重复提交。

### 16.8 成功状态

- 收藏成功：心形状态立即变化，必要时显示 3-4 秒 Toast。
- 新建歌单成功：局部列表立即出现，Toast 提供“查看”。
- 从队列移除：行先退出，Toast 5 秒内提供“撤销”。
- 登录成功：头像替换账号入口，不弹全屏成功页面。
- 评论发布成功：评论就地出现，并在服务确认前显示可读的发送中状态。

## 17. 页面视觉规格

### 17.1 首页 / 每日推荐画廊

- 使用 `immersive-fixed` AppShell。
- 左上 `ECHOFORM`，中上 `DAILY SIGNAL · 日期` 和有限进度，右上搜索与账号。
- 画廊位于视口视觉中心，不靠右堆成缩略图栏。
- 日推是有限序列，不无限循环；首尾项目可准确居中。
- 左下显示当前索引、歌名和艺术家；播放后底部出现持久播放器。
- 游客模式展示公共精选，登录后切换个人日推；切换保留画廊边界稳定。
- 封面色只影响悬停、焦点和局部画布，不让每张窄切片产生独立彩色背景。

### 17.2 歌曲预览舞台

- 仍属于首页空间，不是独立厚重 Modal。
- 中央完整封面、歌名、艺术家、专辑、推荐理由、播放和 `EXPLORE`。
- 文字使用选中封面的可读主题前景。
- 返回可用滚轮、`Escape`、返回按钮，三者进入同一退出状态。
- 滚轮提示不长期写在屏幕上，交互应通过自然反馈被理解。

### 17.3 完整播放页

- Desktop 使用封面 / 歌词双主栏，控制位于稳定底部区域。
- 当前歌词是最高文字层级，封面是最高图像层级，两者不互相遮挡。
- 背景可受音乐强度轻微呼吸，但不显示持续粒子雨、旋转光球或高频频谱。
- 评论和队列共用右侧 Drawer；同一时刻只打开一个。
- 音质、播放模式和计时是低层级信息，不做彩色 Badge 海。
- 页面允许歌词区域纵向滚动，滚轮绝不触发退出。

### 17.4 搜索

- 搜索是一级功能，不藏在 About 或二级菜单。
- 顶部搜索框，下方 SearchField 建议 / 历史，再下方歌曲、歌手、专辑 Tabs。
- 结果优先使用 TrackRow 和清晰列表；歌手与专辑可使用无外层卡片的网格。
- 搜索页面不使用 WebGL 持续动画，保证输入响应和结果扫描效率。
- Query、Type 写入 URL，刷新和返回后恢复状态。

### 17.5 专辑与歌手详情

- 顶部使用大封面 / 艺术家图与标题信息，下面直接进入曲目或专辑列表。
- 介绍文字控制行宽，不覆盖图片，不使用营销 Hero 分栏卡片。
- 主要动作是播放；收藏、分享、更多操作降为次级。
- 长列表使用分隔线和 TrackRow，不把每首歌做成 Card。

### 17.6 音乐库与歌单

- 任务导向，使用 `content-scroll` 和安静背景。
- Tabs 区分喜欢、歌单、历史；不使用三套不同页面导航。
- PlaylistTile 网格与 TrackRow 列表可以切换，但同一屏只保留一种主视图。
- 编辑模式明确显示选择和操作栏；离开时恢复普通浏览密度。

### 17.7 用户主页

- 头像从右上角共享元素进入页面头部。
- 第一视口显示用户名、简短资料、喜欢音乐和歌单摘要。
- “音乐品味画像”使用文字、标签和可访问图表，不使用玄学分数或装饰雷达图。
- 无数据时说明需要更多播放记录，不伪造画像。
- 自己的主页显示设置入口；他人公开主页不显示编辑控件。

### 17.8 设置

- 使用标准纵向表单和分组，不使用沉浸式背景。
- 主题选择使用 Segmented Control；二元项使用 Switch；音质使用菜单或 Radio Group；定时停止使用菜单和步进控件。
- 每个设置有持久 Label，复杂项有 Helper Text。
- 保存失败显示在对应设置旁；可即时生效的选项不增加多余“保存”按钮。

## 18. 响应式行为

### 18.1 Desktop 1440

- 四角与中上导航完整显示。
- 画廊至少能感知 4 个封面切片及轨道方向。
- 完整播放页采用双栏；评论 / 队列用侧 Drawer。
- PlayerTransport 居中，歌曲信息在左，歌词 / 队列 / 音量在右。

### 18.2 Tablet 768

- 顶部上下文缩短，不与品牌和账号重叠。
- 首页画廊缩小但仍居中，不退化成靠右缩略图。
- 完整播放页根据横竖屏切为窄双栏或上下单栏。
- Drawer 最大宽度受视口限制，必要时转为覆盖式面板。
- PlaylistTile 最少 3 列或根据内容宽度降为 2 列。

### 18.3 Mobile 390

- 顶部保留完整品牌、搜索和头像，不显示底部一级导航。
- 迷你播放器位于底部安全区上方，并为内容预留固定安全区。
- 首页约显示 3 个窄封面，提供上一首 / 下一首可见替代控制。
- 横向拖动和纵向手势区域不得与系统返回手势冲突。
- 完整播放页封面置顶、歌词居中、主控制固定在可达区域；评论和队列使用 BottomSheet。
- 搜索输入 48px 高，正文不小于 16px，所有主要触控目标至少 44px。
- 横屏仍可操作播放、退出和搜索，不允许内容被安全区切掉。

### 18.4 内容优先级折叠

缩小屏幕时按以下顺序隐藏或折叠：

1. 辅助说明和重复上下文。
2. 专辑列、音质文字等次级元数据。
3. 低频操作进入 Overflow Menu。
4. 永远保留歌曲名、艺术家、播放 / 暂停、返回、搜索和账号状态。

禁止通过缩小所有文字和按钮解决空间不足。

## 19. 可访问性

### 19.1 对比度

- 普通文字与背景至少 4.5:1。
- 18px 以上大字至少 3:1。
- 图标、边界、焦点和可操作图形至少 3:1。
- ARTWORK 主题每次生成后实时验证，不满足即回退中性主题。
- 错误、成功、播放中和选中态都不能只靠颜色。

### 19.2 键盘

- Tab 顺序与视觉顺序一致。
- `Space` / `Enter` 激活按钮和封面。
- `Escape` 关闭 Dialog、Drawer、BottomSheet 或歌曲预览。
- ProgressRail 和 VolumeControl 支持方向键。
- 画廊提供可聚焦封面和上一项 / 下一项替代，不要求键盘模拟滚轮。
- 路由进入后焦点移到 H1 或主内容容器，返回恢复原触发位置。

### 19.3 屏幕阅读器

- 图标按钮都有具体 `aria-label`，例如“暂停《歌曲名》”，而不是“按钮”。
- 当前播放、缓冲、登录状态和评论提交通过受控 Live Region 播报。
- 封面重复作为背景时使用空 Alt，避免同一内容连续播报。
- Tabs、Dialog、Slider、Switch 使用正确原生语义和 ARIA 状态。
- Toast 不抢焦点；错误区域使用 `role="alert"` 或关联描述。

### 19.4 动态文字与缩放

- 浏览器缩放 200% 时仍可完成播放、搜索、登录和退出。
- 不禁用页面缩放。
- 文本容器允许增长，固定面板在内容溢出时滚动而不是裁掉操作。
- 中文和英文混排不使用固定字符宽度估算。

## 20. 性能与视觉稳定性

- 首页目标 60fps，低性能设备不低于 30fps。
- 单帧主线程预算约 16ms；滚轮和 Pointer 事件节流到动画帧。
- WebGL 只用于首页画廊和明确需要的播放背景；搜索、评论和设置不创建 Canvas。
- 封面优先使用 AVIF / WebP 和正确响应式尺寸。
- 首屏只预加载可见封面和相邻项，远端按移动方向加载。
- 运行时取色使用缩小图或 Worker；不得阻塞播放控制。
- 字体、封面、歌词和列表预留稳定尺寸，目标 CLS 小于 0.1。
- 列表超过 50 项时考虑虚拟化；虚拟化不得破坏键盘焦点和当前播放定位。
- Reduced Motion、低性能模式和 WebGL 失败时仍保留完整功能路径。
- 画廊稳定静止和页面隐藏时无连续 WebGL rAF；滚轮、Pointer、预览状态或可见性恢复将渲染请求合并到下一帧，避免事件风暴。
- raycast 仅在 Pointer、相机、封面布局或交互状态实际变化后执行，鼠标停留不产生无意义的逐帧命中检测。
- 质量层级以运行时帧预算为准：正常层级 DPR 至多 2；受限层级优先降低 DPR、关闭抗锯齿并限制纹理各向异性；仍不足时使用 DOM fallback。质量降级不闪白、不跳位、不改变组件外框。
- 封面纹理只保持可见与相邻窗口，加载中的远端项可取消，离开窗口且不参与预览转场的纹理必须释放；HUD 与 Canvas 尺寸在该过程保持稳定。
- 播放进度采用高频窄订阅或等价受控 DOM 更新。歌词以命中行/词变化为最小 React 更新范围，进度与歌词准确性优先于装饰动画。

## 21. 编码落地规范

### 21.1 文件责任

```text
src/app/globals.css
  Primitive / Semantic / Component Token、主题映射、全局 Reset

src/components/*.tsx
  语义结构、状态 Props、可访问性

src/components/*.module.css
  组件布局、局部状态、动效组合

src/lib/theme/
  ARTWORK 取色、对比计算、主题切换

src/lib/webgl/
  画廊场景、Shader、速度波浪、命中测试
```

新增 `src/lib/theme/` 前应先在对应组件规格中记录目录责任。

### 21.2 CSS 使用

- `globals.css` 中按 Primitive、Semantic、Component、Theme Override 顺序组织。
- Tailwind CSS 4 的 Theme 映射只暴露 Semantic Token，例如 Canvas、Foreground、Border、Action、Status。
- CSS Modules 不出现 Raw Hex，也不直接引用 Primitive 色彩。
- Inline Style 只用于逐帧更新、运行时坐标和 ARTWORK CSS 变量。
- 不使用 `transition: all`；明确列出颜色、透明度或 Transform。
- 媒体查询使用统一断点；不得为单个组件创建相差几像素的私有断点。

### 21.3 React 组件接口

- 使用严格 TypeScript 和判别联合表示状态，避免多个互相冲突的 Boolean。
- 组件接收内部 `Track`、`Album`、`Artist` 模型，不接收网易云原始 Response。
- 异步组件公开 `status`、`error` 和恢复回调，不在内部静默吞错。
- 交互组件使用原生 `button`、`a`、`input`、`dialog` 或等价可访问 Primitive。
- 公共组件不得自行改变全局播放状态，必须调用 Player Provider 暴露的命令。

### 21.4 图标和依赖

- 优先统一使用 Lucide 图标库，不手绘重复 SVG。
- 若项目尚未安装所需依赖，后续实现应在任务范围内单独安装项目依赖，不安装全局包。
- 网易云品牌资产使用官方允许的本地文件，记录来源和授权，不从外站运行时热链。

## 24. 禁止模式清单

后续 Coding 或视觉生成出现以下情况，应直接判定为偏离设计系统：

- 固定紫蓝渐变作为产品主背景。
- 使用渐变光球、Bokeh 或发光圆斑填充空白。
- 每个区块都做成悬浮 Card，或 Card 内再嵌 Card。
- 圆角超过 8px 的普通卡片和大量胶囊按钮。
- 为体现沉浸而隐藏播放、暂停、退出和搜索。
- 在搜索、评论、设置和歌单管理页持续运行 WebGL 装饰。
- 使用 Emoji 作为导航或功能图标。
- 使用负字距或 `vw` 连续缩放文字。
- Hover 改变布局尺寸，导致列表、按钮或封面抖动。
- 用全屏 Spinner 代替稳定骨架和局部加载。
- 错误只显示“失败”或只发 Toast，没有原因和恢复动作。
- 用颜色作为播放中、错误、选中或成功的唯一信号。
- 将网易云 UI、Apple Music、Spotify 或原作品集界面直接换皮复制。
- 为动效完整播放而阻塞用户下一次操作。
- 把首页画廊改成无限循环或在边界累积滚轮输入。
